# CAD Mesh Reconstruction

This panel wraps the bundled CAD Mesh Tool 0.4.1 method A. It does not use Geometry Nodes, a network service, or an LLM. The original object and its mesh are read-only. The addon never saves the current `.blend` automatically.

Choose **Collection** to process every distinct mesh in the input collection and its children. Results go below the chosen output collection, into a branch for that input collection and shared `PASS`, `REVIEW`, and `FAIL` status collections. Choose **Selected Objects** to process selected meshes and link each result beside its source. Previous results remain available. An earlier CAD output can deliberately be selected, or its collection chosen as a later input; it is never automatically fed into the next run. The current output collection cannot be inside the current input collection. Set a persistent Run Folder before starting; for an unsaved `.blend`, use an absolute path.

**Analyze** checks basic eligibility and warns about degenerates and negative scale, but cannot predict every reconstruction failure. CAD reconstruction requires a closed manifold source without boundary edges, edges shared by more than two faces, inconsistent winding, or duplicate faces. If vertices are split, run Blender's Merge by Distance and inspect or repair the resulting topology yourself. The addon does not weld the source. **Reconstruct Selected Operations** prepares an immutable input for each source and runs a separate background Blender worker. Cancel stops the active worker; previously completed outputs remain. The addon imports only a validated, changed mesh. A run that cannot improve any selected region creates no duplicate output.

All operations are enabled by default. Turn off any operation to protect its features from changes, including cleanup. **Circular Holes** detects holes and reduces their perimeter segment count. **Arcs** reduces concave and convex open arcs. **Outer Cylinders** is a separate choice. **Perimeter Loops** adds support rings around circular holes and can run by itself on a manually selected earlier hole result. **Background Cleanup** and **Merge Straight Walls** are separate passes. Every run uses the object or collection the user explicitly chose; there is one run button, not an automatic chain.

When Perimeter Loops is enabled, the baseline support-ring method is tried first. If no safe ring fits but direct joining is valid, the hole is joined directly and the result is marked partial for review. If neither is safe, that feature is preserved and bounded recovery attempts continue with other regions. Every accepted candidate and the final output must pass topology, edge-role, intersection and sampled surface-deviation validation. Triangle reduction is reported as an optimization objective, not a geometry-safety check: a perimeter-only pass may add triangles by design, and an unchanged or higher final triangle count in a reduction run is flagged for review. Circular and open-arc sampling uses ordered distinct source vertices and never asks for more segments than the source provides. Retained rim samples keep their source positions.

Generated partial results have a nonempty `CAD_Skipped` vertex group for preserved features and unmet perimeter requests. `CAD_Review_Constrained` can mark retained uneven rim samples. These groups never modify the source. `candidate.json` and `vertex_map.json` record explicit source-to-candidate-to-final vertex IDs (`-1` denotes a removed/unmapped vertex); `manifest.json` records exact feature IDs and technical reasons. `REPORT.md` gives a short English explanation and review guidance. If no valid changed mesh exists, `failure.json` and `REPORT.md` explicitly state that no output was created.

The worker records the result's world transform in its manifest. Import restores it before parenting so generated geometry remains in the same scene location as its source, including translated/rotated parent hierarchies. An artifact without a valid transform is rejected rather than silently placed at the world origin.

Green `PASS` means all selected operations completed and geometry validation passed, **not** that every CAD detail was identified. Yellow `PARTIAL / REVIEW` means a validated mesh exists but at least one feature or later step was preserved or omitted; inspect `CAD_Skipped` and the report. Red `FAIL` means no validated changed mesh was imported. Visual review remains necessary for every status.

Imported `PASS` and `REVIEW` results receive object colors. **Show** enables a colored wireframe overlay only on generated CAD results in the active viewport; **Hide** removes it. Neither button changes Solid/Wireframe shading modes or colors unrelated objects. The overlay is viewport-local and is cleared when the addon unregisters or another `.blend` loads.

**Retry** starts a new run. The default normal check uses Blender-topology roundtrip calibration. Advanced Manual Normal Limit accepts any positive finite angle in degrees after risk acknowledgement. Above 0.05 degrees, shading may visibly change. This overrides only the straight-wall corner-normal limit; topology, intersection, deviation, and other geometry checks remain enabled. A higher limit cannot guarantee success. The chosen value is stored in the run profile and report.

## Development notes

### Baseline and selectively retained fixes

Commit `4939ec2` is the behavioral reference. The default reconstruction tries its support-ring perimeter before direct joining. The previous unconditional direct-join shortcut was not retained as the default. The following uncommitted fixes were retained because they prevent concrete regressions: full-circle phase alignment, a no-upsampling segment cap, distinct ordered rim samples with identity aliases, preservation of unchanged rim positions, manifold preflight, explicit vertex provenance and diagnostic groups. Direct joining remains a validated fallback for a clear near-edge hole or an explicit holes-only run. Global auto-weld and speculative feature skipping without a validated shared boundary are not used. Geometry validation is never relaxed to obtain a partial result; only the triangle-reduction objective is reported separately.

The `cad_mesh_tool` package started as a vendored copy of the user's local CAD Mesh Tool 0.4.1 source (`E:\WORK\00_VIBE\Blender_geo_nodes\cad_mesh_tool`). It also contains integration and geometry fixes maintained in this addon. Keep the bundled worker and API from the same revision: `code_hash()` binds preparation to worker/import. The addon module `cad_reconstruction` owns Scene settings, modal orchestration, placement and UI. The worker executes in a separate Blender process, never a Python thread accessing live `bpy` data.

Known limits: recovery is deterministic and bounded, not a proof of the maximum possible safe subset. A geometry-valid partial result still needs visual inspection. The CAD core captures positions, topology, corner normals and face material indices, but does not currently transfer arbitrary UV, color or custom attribute layers to a reconstructed output. The current input contract remains closed, consistently wound manifold meshes without unapplied modifiers. Runtime coverage here includes Blender 4.5 and 5.2; the declared 4.2 minimum still needs a dedicated installation test before release.

Run `tests/blender_cad_reconstruction.py`, `tests/blender_cad_operations.py`, `tests/blender_cad_partial.py`, `tests/blender_cad_edge_hole.py`, `tests/blender_cad_arc.py`, and `tests/blender_cad_uneven_arc.py` in headless Blender and verify the extension build before distributing. `tests/blender_cad_production.py` is an optional run against the user-supplied production .blend; it never saves that file. Worker run artifacts live outside the extension directory. The baseline reference is commit `4939ec2`; selective-operation and recovery changes can be rolled back without altering source meshes.
