# CAD Mesh Reconstruction

This panel wraps the bundled CAD Mesh Tool 0.4.1 method A. It does not use Geometry Nodes, a network service, or an LLM. The original object and its mesh are read-only. The addon never saves the current `.blend` automatically.

Choose **Collection** to process every distinct mesh in the input collection and its children. Results go below the chosen output collection, into a branch for that input collection and shared `PASS`, `REVIEW`, and `FAIL` status collections. Choose **Selected Objects** to process selected meshes and link each result beside its source. Previous results remain available. An earlier CAD output can deliberately be selected, or its collection chosen as a later input; it is never automatically fed into the next run. The current output collection cannot be inside the current input collection. Set a persistent Run Folder before starting; for an unsaved `.blend`, use an absolute path.

**Analyze** checks basic eligibility and shows a short blocker/note summary; expand it for more messages. It cannot predict every reconstruction failure. Normal CAD reconstruction requires a closed manifold source without boundary edges, edges shared by more than two faces, inconsistent winding, or duplicate faces. If vertices are split, run Blender's Merge by Distance and inspect the resulting topology: welding alone can create non-manifold junctions. The addon never welds the source. **Reconstruct** prepares an immutable input for each source and runs a separate background Blender worker. The guarded **Try Non-Manifold Mesh** button keeps its warning in its tooltip and still asks for confirmation. **Concurrent Workers** controls how many objects run in separate Blender processes at once (1-16, default 4); it does not make one object faster. Eight or more workers require confirmation because RAM use can grow substantially. The selected limit is never silently reduced, but a batch cannot spawn more workers than source objects. Preparation and import stay on Blender's main thread, one item per modal tick. Results keep source order even when workers finish out of order. Cancel stops all active workers and discards queued work; previously completed outputs remain. A failure on one source is reported separately and does not stop other sources. The addon imports only a validated, changed mesh. A run that cannot improve any selected region creates no duplicate output.

**Try Reconstruct Non-Manifold Meshes** is a separate, confirmation-gated run button. It accepts otherwise closed meshes with edges shared by more than two faces; open boundaries, duplicate faces and inconsistent winding remain blockers. The original non-manifold edges and a dependent source-face patch are preserved exactly. Features touching that patch are skipped, while other selected operations are attempted. A mixed selection or collection processes healthy objects normally and uses preservation only where required. This does **not** repair the original defect. Any changed output from this mode is yellow `PARTIAL / REVIEW`, with a nonempty `CAD_Skipped` group and an explicit report of preserved edges and faces. If safe isolation or full validation fails, that object gets no output and the batch continues. The guarded mode can take several minutes on a feature-dense mesh because each accepted region is checked independently.

All operations are enabled by default. Turn off any operation to protect its features from changes, including cleanup. **Circular Holes** detects holes and normally reduces their perimeter segment count. **Preserve Curve Segmentation** is a separate option, off by default. When enabled, it prevents circular-hole, arc and outer-cylinder resampling while leaving selected Perimeter Loops and Background Cleanup available on unchanged contours. It is not an operation by itself: select at least one actual operation. **Arcs** normally reduces concave and convex open arcs. **Outer Cylinders** is a separate choice. **Perimeter Loops** adds square support rings around circular holes and can run by itself on a manually selected earlier hole result. The nearby **Clearance (mm)** field sets the preferred nominal gap between a circular hole radius and the square's nearest side; `0` keeps automatic sizing. If it does not fit or fails quality checks, smaller values are tried, never a larger one. The selected nominal gap is recorded in the run report. Compound cutouts still use their existing separate sizing logic. **Background Cleanup** and **Merge Straight Walls** are separate passes. Every run uses the object or collection the user explicitly chose; both run buttons use the same selected operations, not an automatic chain.

With Preserve Curve Segmentation enabled, the baseline support-ring method is tried even if the circular hole needs no segment reduction. If no safe ring fits but direct joining is valid, the hole is joined directly and the result is marked partial for review. If neither is safe, that feature is preserved and bounded recovery attempts continue with other regions. Every accepted candidate and the final output must pass topology, edge-role, intersection and sampled surface-deviation validation. An unchanged or higher triangle count is not by itself failure: perimeter loops may add triangles, while planar cleanup can remove edges without changing the triangulated count. The report and Results panel show actual created loops, direct joins, skipped holes, removed planar edges and ngon counts. Circular and open-arc sampling uses ordered distinct source vertices and never asks for more segments than the source provides. Retained rim samples keep their source positions.

Generated partial results have a nonempty `CAD_Skipped` vertex group for preserved features, non-manifold patches and unmet perimeter requests. `CAD_Review_Constrained` can mark retained uneven rim samples. These groups never modify the source. `candidate.json` and `vertex_map.json` record explicit source-to-candidate-to-final vertex IDs (`-1` denotes a removed/unmapped vertex); `manifest.json` records exact feature IDs and technical reasons. `REPORT.md` gives a short English explanation and review guidance. If no valid changed mesh exists, `failure.json` and `REPORT.md` explicitly state that no output was created.

CAD reconstruction ignores source custom split normals by default. It uses geometric face normals for planning and regenerates output normals, without changing the source. Authored sharp edges are tracked through explicit vertex maps and retained where possible. Losing a sharp edge is a shading-review warning, not a geometry failure: a geometrically valid changed mesh is marked `PARTIAL / REVIEW`, and the lost source vertex pairs plus any mappable `CAD_Review_SharpEdges` group are reported. Topology, intersection and surface-deviation checks remain mandatory. The Advanced Manual Normal Limit still applies only to straight-wall cleanup.

The worker records the result's world transform in its manifest. Import restores it before parenting so generated geometry remains in the same scene location as its source, including translated/rotated parent hierarchies. An artifact without a valid transform is rejected rather than silently placed at the world origin.

Green `PASS` means all selected operations completed and geometry validation passed, **not** that every CAD detail was identified. Yellow `PARTIAL / REVIEW` means a validated mesh exists but at least one feature or later step was preserved or omitted; inspect `CAD_Skipped` and the report. Red `FAIL` means no validated changed mesh was imported. Visual review remains necessary for every status.

The Reconstruction Options use two-column toggle buttons; hover each for its full explanation. Results start collapsed to short English status lines; expand a row for counts, technical reason and actions. New CAD outputs keep their source object's normal viewport color. **Show** saves the current viewport shading mode and color choices, then switches its Solid/Wireframe color source to Object Color. Material/Rendered preview temporarily changes to Solid. Only generated CAD output objects receive status colors; unrelated object color data never changes. Blender will nevertheless display all scene objects using their existing Object Color while this viewport mode is active. **Hide** restores every viewport where Show was used and restores original CAD output colors. Clear Results and addon unload also restore them.

**Archive & Clear** writes a readable result history to a Blender Text datablock and clears the panel; save the `.blend` to keep that archive. **Clear Results** discards the panel history without an archive. Both keep source meshes, output meshes and run folders. New CAD outputs retain their status on the object, so Show still works after clearing panel history. **Delete Run Files** is a separate, irreversible action for verified CAD worker subfolders directly inside the currently selected Run Folder; it removes source snapshots, reports, logs and intermediate `.blend` artifacts, not scene objects. Its confirmation includes the folder count. If several `.blend` projects share the Run Folder, their verified CAD runs are included. A deleted run loses its Run Files link, although an existing output mesh stays in the scene. All cleanup actions are disabled during a CAD batch.

**Retry** starts a new run. The default normal check uses Blender-topology roundtrip calibration. Advanced Manual Normal Limit accepts any positive finite angle in degrees after risk acknowledgement. Above 0.05 degrees, shading may visibly change. This overrides only the straight-wall corner-normal limit; topology, intersection, deviation, and other geometry checks remain enabled. A higher limit cannot guarantee success. The chosen value is stored in the run profile and report.

## Development notes

### Baseline and selectively retained fixes

Commit `9e1befa` is the checkpoint for selective operations and bounded partial recovery; `4939ec2` remains the older behavioral reference. The default reconstruction tries its support-ring perimeter before direct joining. The previous unconditional direct-join shortcut was not retained as the default. Full-circle phase alignment, a no-upsampling segment cap, distinct ordered rim samples with identity aliases, preservation of unchanged rim positions, manifold preflight, explicit vertex provenance and diagnostic groups prevent concrete regressions. Direct joining remains a validated fallback for a clear near-edge hole or an explicit holes-only run. Global auto-weld and speculative feature skipping without a validated shared boundary are not used.

The non-manifold mode is opt-in and uses a distinct topology policy. It closes a protected source-face patch over every feature touching the bad-edge vertices. Reconstruction and cleanup must retain all those face cycles and their Blender-representable local vertex coordinates. Validation compares each original bad edge and its incident faces through explicit source-to-output maps, rejects any new bad edge, open edge, winding error, duplicate, degenerate triangle, intersection or excessive sampled deviation, and retains the usual Euler and perimeter checks. The output is valid **relative to the preserved source defect**, not a manifold mesh. Triangle reduction remains an optimization objective, not a geometry-safety check.

The `cad_mesh_tool` package started as a vendored copy of the user's local CAD Mesh Tool 0.4.1 source (`E:\WORK\00_VIBE\Blender_geo_nodes\cad_mesh_tool`). It also contains integration and geometry fixes maintained in this addon. Keep the bundled worker and API from the same revision: `code_hash()` binds preparation to worker/import. The addon module `cad_reconstruction` owns Scene settings, modal orchestration, placement and UI. The worker executes in a separate Blender process, never a Python thread accessing live `bpy` data.

Distance validation batches 16 sample points and bounds triangle/candidate blocks while retaining the same BVH upper bound, float64 point-triangle calculation, AABB filter and tolerance. On an isolated copy of the six-mesh production scene in Blender 5.2.1, one worker took 668.05 s and four workers took 263.85 s (2.53x batch speedup); peak combined worker working set increased from 302 MB to 1123 MB. All six output candidate JSON files were byte-identical between runs, validation checks and statuses matched, and source fingerprints stayed unchanged. `Těleso1.027` produced a validated partial `REVIEW` result with the original non-manifold junction preserved. These are workload-specific measurements, not a guaranteed speedup. A sweep-and-prune intersection prototype produced identical pairs but improved estimated whole-validation time by only 1.9%, 9.5%, and 3.1% on three CAD fixtures, below the 10% adoption threshold, so the original broad phase remains in production.

Preserve Curve Segmentation is deliberately opt-in. On isolated `Těleso1.027` in Blender 5.2.1, the normal guarded workflow produced `REVIEW` in 212 s with 52 skipped features. With preservation enabled it produced a validated `REVIEW` in 321 s: 0 segments reduced, 50 support loops created, 1,511 planar edges removed, 62 final ngons and 12 skipped features. Both runs left the source fingerprint unchanged. The extra runtime is workload-specific, not a performance promise. The new mode does not attempt a broader patch-transaction rewrite or guarantee that every detected hole receives a loop.

Known limits: recovery is deterministic and bounded, not a proof of the maximum possible safe subset. A geometry-valid partial result still needs visual inspection and the preserved non-manifold junction must be repaired manually if a manifold mesh is required. The CAD core captures positions, topology, sharp edges and face material indices, but does not currently transfer arbitrary UV, color or custom attribute layers to a reconstructed output. Source custom normals are intentionally not retained. The ordinary input contract remains a closed, consistently wound manifold mesh without unapplied modifiers. The guarded contract accepts only pre-existing non-manifold edges in otherwise closed, consistently wound meshes. Runtime coverage here includes Blender 4.5 and 5.2; the declared 4.2 minimum still needs a dedicated installation test before release.
